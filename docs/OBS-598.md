## Design question routing
- The question "why do we need to run a blockchain relayer ourselves? can't we rely on another service so we don't need to worry about security?" was routed to the **System Architect** per the PM's direction (OBS-673, child of OBS-468, owned by the System Architect, due 2026-11-05).
- The System Architect's answer (OBS-673, posted 2026-11-01T16:08:55Z): our smart contract accepts writes from exactly one key, so someone on our side must hold it. Moving the server to another provider does not move the key or reduce our exposure; only handing the key (or the trust) to an outside service would, and that makes security worse and changes **what** is deployed rather than **where**. Recommendation: run our own relayer on Fly.io, inside the already-approved $9.44/month plan / $25.00/month ceiling. Host choice (Fly.io vs Vultr vs Netlify) leaves the December audit scope — and its fixed dates — unchanged; an outside submitting service would not.
- The design question has been answered (OBS-673 is done). The pending human access card (ID `287ff977-3606-414f-b379-94da782d7538`) authorizes an account and an API token only, no provisioning, no deploy and no spend — and the Architect's answer is an input to that decision, not a substitute for it.
